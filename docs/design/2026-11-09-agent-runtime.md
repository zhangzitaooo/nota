# Nota Agent 运行环境与模型选择

已确认的设计：默认 Agent 在设置页选择，对话菜单也允许切换；输入框右侧、发送键左侧提供“模型 · 推理强度”入口。弹层分为概览、Agent 列表、模型列表、推理强度列表，子页在同一弹层内切换。选项来自运行时，修改从下条消息生效。侧栏可拖拽调宽并在本机记忆。

Nota Agent 使用 DeepSeek Harness SDK 运行时，由 Nota 启动并配置。共享服务端网关持有 DeepSeek 凭据，客户端只持有独立访问令牌；界面不提供 API Key 表单。固定 DeepSeek V4.1 Flash，不提供 Pro。Codex 与 Claude Code 保持原生会话及用户登录态。每个主题保存各 Agent 的会话 ID；切换时补齐未见过的必要对话，草稿和引用不变。OpenCode 与 Gemini 保留待接入状态。

所有适配器使用论文专属工作目录。原始资料通过只读资源服务访问，产物写入 work 目录。固定阅读规则在会话配置中注入；每轮只新增问题、阅读位置和冻结选区。完整论文、译文、图表和目录按需读取，不再每轮附加前十万字符。

通用运行能力包含文件与 Bash、搜索与网页读取；真实权限请求在对话内一次性确认。论文 MCP 服务提供 search/read/figure，不提供自动批注写入。工具执行状态轻量展示。用户界面不展示能力清单。

实施顺序：1. 工作目录与资源/MCP 服务；2. 原生模型目录、配置持久化、权限桥；3. DeepSeek 运行时与凭据；4. 模型菜单与设置；5. 回归测试、真实调用、流式回答/恢复及界面验证。

验收：模型及推理选项真实可用；忙碌时修改仅影响下一轮；主题/草稿/批注保留；长论文按需读取；Bash 与联网可执行；越界操作经过实际审批；共享 Key 不进入客户端或代码；服务未开通时如实提示。
